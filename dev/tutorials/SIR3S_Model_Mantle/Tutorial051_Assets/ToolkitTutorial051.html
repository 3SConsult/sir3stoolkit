Tutorial 51: Manual Creation of Element Dataframes

This Example demonstrates the capabilities of the class Dataframes_SIR3S_Model that extends SIR3S_Model be abilities to work directley with pandas dataframes. It is shown how to create dataframes containing information about elements such as Nodes, Pipes, etc. existing in a SIR 3S Model. The methods presented are manual, user-defined and detailed. For creating more general dataframes with less input necessary, see Tutorial 52.

Open Model

The tutorial uses Network 3, a fictional district heating network shared by the mantle tutorials: a heat plant (in its own container “Heizwerk”), about 180 consumers, a ring road and two longitudinal sections, calculated over one day. It is built from scratch with the SIR 3S Toolkit by Network3.py; Network3.db3 is included in the tutorial’s ZIP archive.

Its elements have unique ID references (IDREFERENZ), e.g. VL-HS-01 for the first supply pipe of the main street. They are used below to look up tks with GetTkFromIDReference() - the tks themselves differ between builds of the model.

Manual Dataframe creation

Object type reference

Before building dataframes, it helps to know what an element type offers. get_object_type_reference() looks an element type up in the object type reference shipped with sir3stoolkit - the same content as the Object Types, Properties, and Result Value Types section of the API documentation. It needs no open model, and logs the reference’s notice with every call.

[10]:

node_reference = s3s.get_object_type_reference(s3s.ObjectTypes.Node)

[2026-11-25 16:22:41,238] INFO in sir3stoolkit.mantle.dataframes: [object type reference] Aggregated global view across configured network types. The below sections lists all table names from self.ObjectTypes_TableNames, along with their properties, result properties, and respective object type from self.ObjectTypes (needed for toolkit operations like self.InsertElement(), self.GetPropertiesOfElementType()). Result properties additionally list a Description and Standard Physical Unit where known, sourced from SIR 3S's own .MX1 output plus a handful of manual additions (see result_props_descriptions.ipynb). Both are in German, as embedded in SIR 3S itself. Use sir3stoolkit.mantle.dataframes.SIR3S_Model_Dataframes.get_result_file_properties to check what physical units were actually used in your local calculation, which can deviate from the standard physical units here. Each object type lists its Object Category - determined via the Toolkit API where possible, by hand otherwise, Unknown where neither was certain - and the toolkit method to create it, where one was shown to create a real instance of it (see object_types_categories.ipynb).

Besides the properties, it tells the table code, the object category, the toolkit method(s) to create an element of this type and the network types it can be inserted into:
